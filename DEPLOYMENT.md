# MindCheck Deployment Guide

## Backend Deployment on Render

### Prerequisites
- GitHub repository connected: ✅ https://github.com/MuhammadAbdullah990/mindcheck.git
- Neon PostgreSQL database (get your DATABASE_URL ready)
- Render account (free tier available)

### Step 1: Deploy to Render

1. **Go to Render Dashboard**
   - Visit https://dashboard.render.com
   - Sign in with your GitHub account

2. **Create New Web Service**
   - Click "New +" → "Web Service"
   - Connect your GitHub repository: `MuhammadAbdullah990/mindcheck`
   - Render will automatically detect `render.yaml`

3. **Configure Environment Variables**
   
   In the Render dashboard, set these environment variables:
   
   ```
   NODE_ENV=production
   DATABASE_URL=<your-neon-pooled-connection-string>
   JWT_SECRET=<auto-generated-by-render>
   JWT_EXPIRES_IN=7d
   CORS_ORIGIN=https://your-frontend-url.vercel.app
   CLIENT_URL=https://your-frontend-url.vercel.app
   ```

   **Important:** 
   - Use the **POOLED** connection string from Neon (ends with `-pooler.us-east-2.aws.neon.tech`)
   - Replace `your-frontend-url` with your actual Vercel URL
   - JWT_SECRET will be auto-generated, or create your own with:
     ```bash
     node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
     ```

4. **Deploy**
   - Click "Create Web Service"
   - Render will:
     - Install dependencies
     - Generate Prisma client
     - Build the TypeScript code
     - Run database migrations
     - Seed the database
     - Start the server

5. **Monitor Deployment**
   - Watch the logs in the Render dashboard
   - Look for: "MindCheck API listening on..."
   - Your API will be available at: `https://mindcheck-api.onrender.com`

### Step 2: Update Frontend Configuration

Once your backend is deployed, update the frontend to use the production API URL.

**File to update:** `client/.env.production` (create if it doesn't exist)

```env
VITE_API_URL=https://mindcheck-api.onrender.com/api
```

Or add it to Vercel environment variables:
1. Go to your Vercel project settings
2. Navigate to "Environment Variables"
3. Add: `VITE_API_URL` = `https://mindcheck-api.onrender.com/api`
4. Redeploy the frontend

### Step 3: Verify Deployment

Test your API endpoints:

```bash
# Health check
curl https://mindcheck-api.onrender.com/api/health

# Get assessments
curl https://mindcheck-api.onrender.com/api/assessments

# Get resources
curl https://mindcheck-api.onrender.com/api/resources
```

Expected response from health check:
```json
{
  "success": true,
  "data": {
    "status": "ok",
    "timestamp": "2026-10-09T...",
    "database": "connected"
  }
}
```

### Step 4: Database Migrations (Future Updates)

When you update the database schema:

1. Push your changes to GitHub
2. Render will automatically:
   - Rebuild the service
   - Run `prisma migrate deploy`
   - Restart the server

Or manually trigger migration:
```bash
npm run db:deploy --workspace server
```

## Troubleshooting

### Build Fails
- Check that `render.yaml` build command is correct
- Verify all dependencies are in `package.json`
- Check Render logs for specific errors

### Database Connection Fails
- Verify DATABASE_URL is the **pooled** connection string
- Check that Neon database is running
- Ensure `?sslmode=require` is in the connection string

### CORS Errors
- Verify `CORS_ORIGIN` matches your Vercel URL exactly (including https://)
- Check that `CLIENT_URL` is also set correctly
- No trailing slashes in URLs

### API Returns 500 Errors
- Check Render logs: Dashboard → Your Service → Logs
- Verify all environment variables are set
- Ensure migrations ran successfully

## Render Free Tier Limitations

- **Cold starts**: Service spins down after 15 minutes of inactivity
  - First request after sleep takes ~30-60 seconds
  - Subsequent requests are fast
- **750 hours/month** free (enough for one always-on service)
- **No custom domains** on free tier (use `.onrender.com`)
